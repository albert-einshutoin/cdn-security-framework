# Fixed public NestJS source Pilot

This is one reference application and one fixed commit, not a production application sample. The source is [lujakob/nestjs-realworld-example-app at `c1c2cc4e448b279ff083272df1ac50d20c3304fa`](https://github.com/lujakob/nestjs-realworld-example-app/tree/c1c2cc4e448b279ff083272df1ac50d20c3304fa). `package.json` says `ISC`; this commit has no separate LICENSE file. The raw acquired archive hash is `sha256:8a2448be768be75142ace6a105f15275af4460c14c1707f26d148433d3194019`. A pre-push privacy check found a local MySQL credential URL in the upstream `prisma/.env`. That one non-source file is excluded from the committed 249,561-byte evaluation `source.tar.gz` (`sha256:0f3bca4a2e2acb472d8280acd2a6857213ca57865ac78de5449d90c833f69970`), which has 118 regular files, no symlinks or escaping paths. All retained file bytes were compared with the fixed commit. The omitted credential content is not copied into evidence. The evaluation source tree is unchanged during analysis. No application code, install hook, Guard, script, DB, credential endpoint, or runtime Swagger generation is executed.

Candidate comparison was limited to two repositories. `brocoders/nestjs-boilerplate` was rejected before analysis because its relevant controllers use an object-form `@Controller({ path, version })` outside the current static path resolver. Its fixed candidate commit was `9620f159eefe38f47747d02ab162852367c5472c` (MIT). The selected repository offers 19 static routes across article, profile, and user controllers plus auth documentation and middleware evidence. [Independent expectations](EXPECTATIONS.md) and [`expectations.json`](expectations.json) were committed and independently reviewed before the first analyzer run.

## Evaluation boundary

- Unit: 19 predeclared decorator-local method/path pairs. The analyzer extracted all 19. It also extracted `GET /tags` and `GET /`, which the prior scope explicitly placed outside evaluation. These two cause the baseline `SC-INVENTORY-001` findings against the deliberately limited evaluation OpenAPI; they are not product false positives or upstream application defects.
- No static upstream OpenAPI or Edge Policy exists in the snapshot. `openapi-evaluation.json` and `policy-evaluation.yml` are controlled evaluator contracts, not natural drift against the original app. The explicit auth mapping is empty. The `auth-unknown-control` mutation maps an unused Guard name and still must not create a definite Source auth conclusion.
- The runtime `api` global prefix in `src/main.ts:8` is outside current analyzer support, so only decorator-local paths are compared. `@ApiBearerAuth` is documentation, and module `AuthMiddleware` maps do not establish enforcement. All 19 scoped auth conclusions remain `unknown`. The analyzer emits one `SOURCE_ANALYZER_GLOBAL_GUARD_UNSUPPORTED` diagnostic at `src/app.module.ts:11` because an imported module cannot be ruled out as a global provider. Authentication behavior, reachability, and actual security are not certified.
- The 54 baseline SARIF findings are 12 `SC-EXPOSURE-001`, 14 `SC-EXPOSURE-005`, 2 `SC-INVENTORY-001`, 7 `SC-LIMIT-002`, and 19 `SC-AUTHN-004`. The evaluation Policy/OpenAPI choices produce these. They are not counted as 54 discovered defects; only the fixed, independently grounded route and deliberate mutation units are scored.

## Repeat

1. Obtain the **same run** single-pack candidate and verify it with its `scripts/single-pack.js verify` and `CSF_SOURCE`, `GITHUB_RUN_ID`, `GITHUB_RUN_ATTEMPT`, and `CSF_TGZ_SHA256` identity environment variables. Install its `consumer` with `npm ci --ignore-scripts --no-audit --no-fund`.
2. Run `node test/pilot/realworld/pilot.cjs prepare <new-dependency-dir>` while network access is allowed. The fixed archive and derived lock are checked, and target install hooks are disabled.
3. Disable network for the analysis process. Run `node test/pilot/realworld/pilot.cjs evaluate <candidate-dir> <dependency-dir> <new-work-dir> <new-safe-result.json>`, then `node test/pilot/realworld/pilot.cjs verify <candidate-dir> <work-dir> <safe-result.json> <new-safe-stage-dir>` with the same identity environment. The runner uses the installed CLI and internal CI driver, checks all 19 operations, seven case outcomes, local stage transfer, input hashes, report hashes, and privacy. Detailed Summary/SARIF stay local; only the validated aggregate `safe-result.json` is allowed into the branch-only hosted artifact.
4. The branch-only `source-aware-pilot` workflow job reuses the ordinary single-pack producer and package acceptance. It prepares dependencies online and calls the evaluator inside Linux `unshare --net`. The ordinary full validation and release matrix remain independent required evidence. An external snapshot case is not a second repository or a new product feature.

The first local runner pass failed because the evaluator's own unused-Guard mapping had the wrong configuration shape; the runner was corrected to `{ "auth_kind": "bearer" }` and a fresh work directory completed all seven cases. This was a harness error, not a product bug. No product defect inside the current supported boundary has been found; no speculative product repair is included.
